# ローカルユーザー一括作成スクリプト v2.2（要件準拠版）

管理者が **CSV をもとに、実行中の Windows 端末へ規定要件に沿ったローカルユーザーを一括作成**するためのスクリプトです。
ps1ファイルはsjis保存すること
users.csvファイルはutf-8で保存すること（使い方の3を実行）

## 適用される要件

| 項目 | 設定内容 | 実装方法 |
|---|---|---|
| ユーザー名 | 英数字のみ・20 文字以内 | 正規表現 `^[A-Za-z0-9]{1,20}$` で検証。違反は作成せずエラー |
| フルネーム | 「姓, 名」形式のローマ字（例: `Sasaki, Ryo`） | CSV の `LastName` / `FirstName` 列から自動生成。大文字小文字も正規化 |
| パスワード | 16 文字以上の英数字記号 | CSV 未記入なら 16 文字を自動生成。記入時は文字数と文字種を検証 |
| 所属グループ | `Users` と `Remote Desktop Users` の 2 つ | well-known SID（`S-1-5-32-545` / `S-1-5-32-555`）で追加 |
| パスワードを無制限にする | **はい** | `New-LocalUser -PasswordNeverExpires` |
| ユーザーはパスワードを変更できない | **いいえ**（変更を許可） | `-UserMayNotChangePassword` を付けない |
| アカウントを無効にする | **いいえ**（有効） | `Enable-LocalUser` |
| アカウントのロックアウト | **いいえ**（解除状態を保証） | ADSI で `IsAccountLocked` を確認し、ロックされていれば解除 |

## ⚠️ 「次回ログオン時にパスワードの変更が必要」について

ご提示の要件のうち、次の 2 つは **Windows の仕様上、同時に設定できません**。

- 次回ログオン時にパスワードの変更が必要: はい
- パスワードを無制限にする: はい

「パスワードを無期限にする」にチェックを入れると、「次回ログオン時にパスワードの変更が必要」のチェックボックスは**グレーアウトして操作できなくなります**。ローカルアカウントでもドメインアカウントでも同じ挙動です。

そこで本スクリプトは、ご指定に従って **「パスワード無期限」を優先**し、次回ログオン時の変更要求は設定しません。

初回ログオン時の変更をどうしても強制したい場合は `-ForceChangeAtLogon` を指定してください。その場合はパスワード無期限が自動的に無効になり、画面にも警告が表示されます。

```powershell
# 「次回変更必須」を優先する場合（無期限は無効になります）
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -ForceChangeAtLogon
```

## 使い方

PowerShell を **「管理者として実行」** で開いてから、スクリプトのあるフォルダーに移動して実行します。

```powershell
cd $HOME\Downloads\local-user-provisioning-v2

# 1. まず何も変更せずに実行内容だけを確認する（推奨）
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -WhatIf

# 2. 実行（Excel 保存の Shift_JIS CSV。既定値なので -Encoding は省略可）
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv

# 3. UTF-8(BOM付き) の CSV の場合
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -Encoding UTF8

# 4. 既存ユーザーも要件どおりに更新する
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -UpdateExisting
```

実行ポリシーで止まる場合:

```powershell
PowerShell -ExecutionPolicy Bypass -File .\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv
```

## CSV の列仕様

**v1 から列構成が変わっています。** 属性の多くはスクリプト側で要件として固定したため、CSV に書く項目は大幅に減りました。

| 列名 | 必須 | 説明 |
|---|:---:|---|
| `Delete` | | **`True` と記入するとそのユーザーを削除**します（**先頭列**）。空欄なら通常どおり作成/更新 |
| `UserName` | ● | ログオン名。**英数字のみ・20 文字以内**（記号・日本語は不可） |
| `LastName` | ● | 姓のローマ字。例: `Sasaki` |
| `FirstName` | ● | 名のローマ字。例: `Ryo` |
| `Password` | | 16 文字以上の半角英数字記号。**空欄なら自動生成**（推奨） |
| `Description` | | 説明・備考。日本語可 |
| `AdditionalGroups` | | 要件の 2 グループに加えて所属させたいグループ。`;` 区切り |

サンプル:

```csv
Delete,UserName,LastName,FirstName,Password,Description,AdditionalGroups
,sasakiryo,Sasaki,Ryo,,営業部,
,tanakat,TANAKA,Taro,,開発部,
,suzukih,suzuki,hanako,Keiri#2026Spring1234,経理部,
,kanri01,Hoshu,Kanri,,保守管理,Administrators
True,taishoku01,,,,退職者,
```

最終行のように `Delete` 列に `True` と書くと、その行は**作成ではなく削除**として処理されます。

### 列の並び順について

**スクリプトは列の並び順を見ていません。** ヘッダー行の**列名**だけで各列を認識するため、`Delete` を先頭に置いても末尾に置いても、途中の列を入れ替えても結果は同じです。上の並び（`Delete` が先頭）は、削除フラグを見落としにくくするための推奨順です。

列名は次のように解釈されます。大文字小文字の違い、前後の空白、BOM は無視します。

| 正規名 | 受け付ける列名 |
|---|---|
| `Delete` | `Delete` / `削除` / `削除フラグ` |
| `UserName` | `UserName` / `ユーザー名` / `ログオン名` |
| `LastName` | `LastName` / `姓` |
| `FirstName` | `FirstName` / `名` |
| `Password` | `Password` / `パスワード` |
| `Description` | `Description` / `説明` / `備考` |
| `AdditionalGroups` | `AdditionalGroups` / `追加グループ` |

表にない列は無視され、実行時に「未使用の列」として警告表示されます。綴り違いはここで気付けます。

```
  認識した列: Delete, UserName, LastName, FirstName, Password, Description, AdditionalGroups
  未使用の列（無視します）: Memo
```

### フルネームの生成規則

`LastName` と `FirstName` から `姓, 名` の形式を組み立てます。大文字小文字は自動で正規化されるため、CSV の入力揺れを気にする必要はありません。

| LastName | FirstName | 生成されるフルネーム |
|---|---|---|
| `Sasaki` | `Ryo` | `Sasaki, Ryo` |
| `TANAKA` | `Taro` | `Tanaka, Taro` |
| `suzuki` | `hanako` | `Suzuki, Hanako` |
| `O'Brien` | `Michael` | `O'Brien, Michael` |
| `Smith-Jones` | `Anna` | `Smith-Jones, Anna` |

アポストロフィやハイフンを含む姓は、区切りの直後も大文字として扱います（`o'brien` → `O'Brien`）。半角英字以外が含まれている場合はエラーになり、そのユーザーだけスキップされます。

### パスワードの扱い

`Password` 列を**空欄にすることを推奨します**。空欄の場合、以下の条件を満たす 16 文字のランダムパスワードを生成します。

- 大文字・小文字・数字・記号を**各 1 文字以上必ず含む**（Windows の「複雑さの要件」ポリシーが有効でも必ず通ります）
- 記号は `! # % & * + - = ? @ _` に限定（コマンドラインへの貼り付けで事故になりにくいもの）
- 紛らわしい文字（`0`/`O`、`1`/`l`/`I`）は除外
- 暗号論的乱数（`RandomNumberGenerator`）を使用

CSV に直接記入した場合は、**16 文字以上**であることと、**半角の英数字記号のみ**であることを作成前に検証します。全角文字や空白が混ざっているとエラーになります。

文字数を変えたい場合は `-MinPasswordLength` で指定できます。

```powershell
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -MinPasswordLength 20
```

## ユーザーの削除（Delete 列）

CSV の先頭列 `Delete` に **`True`** と記入した行は、作成ではなく **削除**が実行されます。

```csv
Delete,UserName,LastName,FirstName,Password,Description,AdditionalGroups
True,taishoku01,,,,2026-03-31 退職,
```

削除行では `LastName` / `FirstName` / `Password` は不要です（空欄で構いません）。列自体は残しておいてください。

`True` のほか `YES` / `1` / `はい` / `削除` も同じ意味として扱います。大文字小文字は区別しません。空欄・`False` などはすべて「削除しない」です。

### 実行前の確認

削除対象がある場合、処理を始める前に**対象の一覧を表示して確認を求めます**。

```
!! 削除対象が 2 件あります !!
     - taishoku01
     - taishoku02

  ユーザーアカウントの削除は取り消せません。
  プロファイル（C:\Users\<名前>）は残ります。併せて削除するには -RemoveProfile を指定してください。

  上記のユーザーを削除します。続行するには 'yes' と入力してください:
```

`yes` 以外を入力すると、**何も変更せずに終了**します（終了コード `2`）。

タスクスケジューラなどから無人実行する場合は `-Force` でこの確認を省略できます。

```powershell
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -Force
```

`-WhatIf` を付けた場合は確認プロンプトは出ず、削除される予定のユーザーが表示されるだけです。

### 誤操作の防止

以下は削除できません。該当行はエラーとして記録され、処理は続行します。

| 対象 | 判定方法 |
|---|---|
| 組み込み Administrator | SID の末尾（RID）が `500` |
| Guest | RID `501` |
| DefaultAccount | RID `503` |
| WDAGUtilityAccount | RID `504` |
| スクリプトを実行中のユーザー自身 | `$env:USERNAME` と一致 |

CSV に書かれたユーザーが**存在しない場合はスキップ**します（エラーにはなりません）。

### プロファイルの扱い

`Remove-LocalUser` はアカウントを削除するだけで、**プロファイルフォルダー（`C:\Users\<名前>`）とその中のデータは残ります**。これは既定の動作で、誤削除時にデータを救済できるようにするためです。

プロファイルごと消す場合は `-RemoveProfile` を指定してください。

```powershell
.\Add-LocalUsersFromCsv.ps1 -CsvPath .\users.csv -RemoveProfile
```

指定した場合は、確認画面にも赤字で警告が表示されます。プロファイルはアカウント削除の**前**に、SID をキーにして `Win32_UserProfile` 経由で削除します（レジストリ側の参照も併せて整理されます）。

### 削除行の作成規則について

削除行には、ユーザー名の命名規則（英数字のみ・20文字以内）の検証を**適用しません**。このスクリプト以外の方法で作られた `old.user` のような名前のアカウントも削除できます。

## 要件適合チェック

作成後、**実際に作られたアカウントを読み戻して要件どおりの状態か検証**し、一覧で表示します。

```
UserName  フルネーム           有効 PW無期限 PW変更可 グループ                           総合
--------  ----------           ---- -------- -------- --------                           ----
sasakiryo Sasaki, Ryo OK       OK   OK       OK       Users=OK / Remote Desktop Users=OK 適合
tanakat   Tanaka, Taro OK      OK   OK       OK       Users=OK / Remote Desktop Users=OK 適合
```

「設定したつもりが反映されていなかった」を防ぐための工程です。1 つでも `NG` があれば総合が `不適合` になります。

## 出力ファイル

| ファイル | 内容 |
|---|---|
| `result-<日時>.csv` | ユーザーごとの処理結果。**自動生成パスワードもここに出力されます** |
| `log-<日時>.txt` | 実行ログ（画面出力の全文） |

`result-*.csv` はアクセス権を Administrators と SYSTEM のみに制限しますが、平文であることに変わりはありません。**配布後は速やかに削除してください。**

```powershell
Remove-Item .\result-*.csv
```

パスワードをファイルに出したくない場合は `-SkipPasswordOutput` を指定してください。

## アカウントのロックアウトについて

要件の「アカウントのロックアウト: いいえ」は、**そのアカウントがロックされていない状態**を指します。本スクリプトは作成・更新のたびにロック状態を確認し、ロックされていれば解除します。

なお、「何回ログオンに失敗したらロックするか」は**端末全体のポリシー**であり、ユーザー個別の設定ではありません。スクリプト実行時に現在の設定を表示します。

```
端末のロックアウトポリシー: ロックアウトのしきい値: 10
```

そもそもロックアウトを発生させない運用にしたい場合は、別途ポリシー側の変更が必要です（端末全体に影響するため、スクリプトからは自動変更しません）。

```powershell
# 現在の設定を確認
net accounts

# ロックアウトを無効にする（端末全体に影響します。実施は慎重に）
net accounts /lockoutthreshold:0
```

## 安全のための設計

| 項目 | 動作 |
|---|---|
| 管理者権限 | 実行時にチェックし、不足していれば何もせず終了 |
| `-WhatIf` | 一切変更せず、実行内容だけを表示 |
| 既存ユーザー | 既定では**スキップ**。上書きは `-UpdateExisting` を明示した場合のみ |
| 入力検証 | ユーザー名・姓名・パスワードを**作成前に**検証。違反行だけをスキップ |
| エラー処理 | 1 件失敗しても止まらず、最後に集計を表示 |
| 事後検証 | 作成後に読み戻して要件適合を確認 |
| 削除の確認 | 削除対象がある場合は一覧を表示し、`yes` の入力を要求（`-Force` で省略可） |
| 削除の保護 | 組み込みアカウントと実行中ユーザー自身は削除不可 |
| プロファイル | 既定では残す。消す場合は `-RemoveProfile` を明示 |
| 終了コード | 失敗が 1 件でもあれば `1`、削除確認で中止した場合は `2`、すべて成功なら `0` |

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| `用語 '.\Add-LocalUsersFromCsv.ps1' は…認識されません` | そのフォルダーにファイルが無い | `cd` で正しいフォルダーへ移動。ZIP は先に展開する |
| `このシステムではスクリプトの実行が無効になっている` | 実行ポリシー | `PowerShell -ExecutionPolicy Bypass -File .\Add-LocalUsersFromCsv.ps1 ...` |
| `CSV に必須列がありません` | 文字コード違い、または列名の綴り違い | `-Encoding` を変更（Excel 保存なら既定の `Default`） |
| `UserName は英数字のみ…` | ドットやハイフンが入っている | 英数字のみに変更（例: `sasaki.ryo` → `sasakiryo`） |
| `パスワードは 16 文字以上…` | CSV のパスワードが短い | 16 文字以上にするか、列を空欄にして自動生成させる |
| `LastName '…' はローマ字で入力してください` | 日本語が入っている | ローマ字表記に変更 |
| `パスワードが複雑さの要件を満たしていない` | ローカルセキュリティポリシー | `Password` 列を空欄にして自動生成させる |
| `正規表現パターン ^??? が無効です` | **スクリプトファイルが Shift_JIS に変換されている**（v2.2 未満） | v2.2 以降を使う。スクリプトは UTF-8(BOM 付き) のまま転送する |
| 「次回ログオン時に変更」が設定されない | 仕様どおり（無期限と排他） | `-ForceChangeAtLogon` を指定（無期限は無効になります） |

## 動作環境

- Windows 10 / 11 / Windows Server 2016 以降
- Windows PowerShell 5.1（OS 標準）または PowerShell 7 以降
- `Microsoft.PowerShell.LocalAccounts` モジュール（OS 標準）

> スクリプトファイルは **UTF-8 BOM 付き**で保存しています。BOM を落とすと Windows PowerShell 5.1 が Shift_JIS として解釈し、日本語のメッセージが文字化けします。編集時はご注意ください。
>
> 転送やエディタでの保存で **Shift_JIS に変換しないでください。** CP932 に無い文字は `?` に置き換えられ、正規表現やメッセージが壊れます。v2.2 では処理に関わる部分を ASCII 文字だけで書いていますが、コメントやメッセージの日本語は UTF-8 前提です。

## 検証済みの動作

Linux 上で `LocalAccounts` コマンドレットをスタブ化して検証済みです。

- 正常系: `Sasaki, Ryo` 形式の生成、大文字小文字の正規化（`TANAKA` → `Tanaka`、`suzuki hanako` → `Suzuki, Hanako`）、アポストロフィ姓（`O'Brien`）、ハイフン姓（`Smith-Jones`）、追加グループ指定
- 異常系: ユーザー名にドット、21 文字以上、パスワード 16 文字未満、空白入りパスワード、全角パスワード、日本語の姓、姓が空
- 16 文字の自動生成パスワードが 4 種の文字種を含むこと
- `-ForceChangeAtLogon` 指定時に無期限が無効化され、適合チェックの期待値も切り替わること
- 削除: 正常削除、組み込み Administrator（RID 500）の拒否、存在しないユーザーのスキップ、確認プロンプトで `no` を入力した際の中止（終了コード `2`）、`-RemoveProfile` によるプロファイル削除
- 全行が削除行の CSV で `LastName` / `FirstName` が空でもエラーにならないこと
- `-WhatIf` で一切の変更が行われないこと（削除も実行されないこと）
- 列の並び順を変えても（`Delete` が先頭でも末尾でも）同じ結果になること
- 列名に BOM の文字化け（CP1252 / CP932 の両方）が混入しても `Delete` 列を認識できること
- BOM 付き CSV の文字コード自動判定
- スクリプトを Shift_JIS に変換しても構文・動作が壊れないこと（CP932 に無い文字が無いこと）


## 変更履歴

### v2.2

- CSV の列順を変更し、**`Delete` 列を先頭に移動**しました。削除フラグが行頭に来るため、一覧を見たときに削除対象を見落としにくくなります。
  既存の CSV（`Delete` が最右列）もそのまま使えます。
- 列の認識方法を見直しました。**列名だけで判定し、並び順には依存しません。**
  - 列名の前後の空白・引用符・**BOM** を無視するようにしました。UTF-8 BOM 付き CSV を `-Encoding Default` で読むと先頭列の列名に `ï»¿` が混入します。従来は先頭列が `UserName` だったため「必須列がありません」というエラーで気付けましたが、先頭列が `Delete` だと**削除列を認識できないまま作成処理に流れる**ため、確実に取り除くようにしました。
  - 大文字小文字の違いを無視するようにしました（`delete` / `DELETE` も可）。
  - 日本語の列名（`削除` / `ユーザー名` / `姓` / `名` など）を受け付けるようにしました。
  - 認識した列と、無視した列を実行時に表示するようにしました。
- 削除行の判定を `Test-DeleteRow` に集約し、値の取り出しをすべて列名解決経由に統一しました（`Group-Object -Property UserName` のような直接参照を排除）。
- **CSV の BOM から文字コードを自動判定**するようにしました（`-Encoding` を明示指定した場合はそちらを優先）。
  UTF-8(BOM 付き) の CSV を既定の `Default`（ANSI）で読むと先頭列の列名が壊れます。先頭列が `UserName` だった頃は「必須列がありません」というエラーで気付けましたが、`Delete` が先頭になると**削除列を見失ったまま処理が進む**ため、根本原因を先に潰すようにしました。
- **不具合修正**: 実行すると `正規表現パターン ^??? が無効です` というエラーで起動できない問題を修正。
  列名から BOM を取り除く処理に Latin-1 の記号（`ï»¿`）を直接書いていたため、スクリプトが Shift_JIS に変換されると CP932 に無いこれらの文字が `?` に置換され、`^???` という不正な正規表現になっていました。
  BOM の見え方はコードページによって変わる（CP1252 なら 3 文字、CP932 なら 2 文字）ため、文字リテラルを書くのをやめ、**実行時に `EF BB BF` を各コードページでデコードして**前方一致で取り除く方式に変更しました。この処理は **ASCII 文字だけ**で書いています。

### v2.1

- **不具合修正**: 処理の最後に `パラメーター名 'WhatIf' に一致するパラメーターが見つかりません` というエラーが出て、終了コードが `0` にならない問題を修正。
  Windows PowerShell 5.1 の `Stop-Transcript` は `-WhatIf` をサポートしないため、指定を削除しました（`Start-Transcript` はサポートするため、そちらはそのままです）。

- 要件適合チェック表の見出しを半角英字に変更。`Format-Table` は全角文字の表示幅を 1 文字として数えるため、日本語の見出しでは区切り線と桁がずれていました。表の下に凡例を表示します。
- 適合チェックの結果、要件を満たさないユーザーがあれば末尾に警告としてまとめて表示するようにしました。
- 一時ファイルのパス取得を `$env:TEMP` から `[System.IO.Path]::GetTempPath()` に変更（SYSTEM 実行時などに `TEMP` が未設定でも動作するように）。
